# DSH-L2D 攻坚组 · 多智能体编排 Skill

## Overview

本 Skill 把一套成熟的多智能体协作治理机制封装为可复用流程。它服务于两类场景：

1. **首次建立团队工作区**：把多智能体编排策略写成团队章程（`docs/<团队名>-团队章程.md`），登记到工作区记忆与账号记忆。
2. **每次新开工项目 / 新工作区启动**：无论是否首次，都先执行「启动协议」——向用户确认四个主导者，再进入任务。

团队名称、项目定位、技术栈在每次建立时由用户提供（默认团队名 `dsh L2D攻坚组`）。策略内核固定，不随项目改变。

## When to use

触发词 / 场景：
- "建立团队"、"建立 Agent team"、"新建团队工作区"、"初始化多智能体协作"
- "新开工项目"、"开个新工作区"、"搭个新项目"
- 用户要求把协作规则 / 角色分工沉淀为可复用机制

**核心约束（用户强制）**：每次新工作区启动，必须先用 AskUserQuestion 询问四主导者，禁止默认跳过。

## Procedure

### Step 1 — 收集团队元信息
向用户确认（或直接采用默认）：
- 团队名称（默认 `dsh L2D攻坚组`）
- 项目一句话定位与技术栈（写入章程 §0）
若无明确信息，先用合理默认，并在章程中标注"待补全"。

### Step 2 — 写入团队章程
将 `references/charter-template.md` 复制到 `<workspace>/docs/<团队名>-团队章程.md`，
填入团队名、项目定位、技术栈与角色映射（按本 Skill 的全局配置）。若为复用已有章程，直接适配而非重写。

### Step 3 — 登记记忆
- 工作区记忆：`<workspace>/.workbuddy/memory/MEMORY.md` 写入团队身份、角色绑定、验收协议、启动协议、全局模型/推理配置；同日 `<workspace>/.workbuddy/memory/YYYY-MM-DD.md` 写入建立日志。
- 账号记忆：`C:/Users/User/.workbuddy/user-a8bdb9ed-2e1b-42b4-b676-6bdb72338682-personal/MEMORY.md`（如不存在则新建）追加一条："多智能体团队工作区启动时须先确认四主导者；默认模型最新 Flash；推理强度高；使用 dsh-l2d-team skill。"

### Step 4 — 启动协议（每次必问）
用 AskUserQuestion 提出四个槽位，列出默认绑定，允许用户逐槽改派或选"Other"自定义：

| 槽位 | 默认 | 说明 |
| --- | --- | --- |
| 前端主导者 | DSV4.1f | 页面/组件/交互/动画/前端框架 |
| 后端主导者 | MiMo | API/数据库/服务端/插件与 MCP |
| 模型调试主导者 | DSV4.1f（可改派） | 模型/动作引擎/能力档案/参数仲裁（按项目定领域） |
| 验收主导者 | GLM | 视觉/多模态/交互验收，须基于真实产物 |

- 用户可逐槽确认默认、改派、或声明"沿用上次"。
- 四槽确认（或声明沿用）后方可进入任务分析与执行。
- 本次确认结果记入当日工作日志，作为授权基线。
- 若本次仅涉单一领域，仍须至少确认相关槽位，其余标"本次不涉及"。

### Step 5 — 执行与验收
按章程 §3 路由、§4 纪律、§5 验收协议推进；每个任务返回结构化报告（Task ID / Assigned Model / Modified Files / Implementation Summary / Tests Executed / Test Results / Known Issues / Remaining Risks / Acceptance Status），状态仅限 PASS / PASS_WITH_WARNINGS / BLOCKED / FAILED。最终合并与发布由 DSV4.1f 决策。

## 全局模型与推理配置（用户强制，覆盖全部角色与任务）

1. **默认模型 = 最新一代 Flash**：团队工作模型统一选用平台当前最新 Flash；代号 DSV4.1f = "当前最新 Flash"，随发布自动跟进。
2. **推理强度 = 高（high）**：DSV4.1f / GLM / MiMo / General Agent 均不降级推理。
3. 例外：GLM 视觉验收如需视觉输入模型可调用；确有非 Flash 专用需求须在任务报告注明。
4. 高推理 ≠ 无谓重复：仍遵循成本约束（优先专业代理、独立任务并行、避免同任务多模型重复）。

## 角色职责绑定（内核，随项目适配领域）

- **DSV4.1f**（总控 + 前端）：规划/架构/前端/集成验收，不得无故交出总控与最终验收权。
- **GLM**（多模态 QA）：独立验收，须基于真实截图/图片/视频，不凭自述判定。
- **MiMo**（后端）：API/数据库/服务端/插件，不擅改前端与共享 UI。
- **General Agent**（通用）：调研/文档/部署/运维/CI-CD/排错及不属于上述专业的任务。
- **模型调试负责人**（领域角色，默认 DSV4.1f，可改派）：项目核心资产调试（如 DSH-L2D 的 Live2D 模型/动作引擎/能力档案/参数仲裁）。

WorkBuddy 环境落地映射：DSV4.1f 由主 Agent 承担；GLM/MiMo/General 可通过派生的 general-purpose 子代理承载，但总控与验收权留在主 Agent；视觉验收用 ViewImage 等视觉能力。
