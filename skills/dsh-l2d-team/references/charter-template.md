## 3. 自动任务路由（Automatic Task Routing）

- **IF** 前端 / UI / UX / 动画：前端实现委派 DSV4.1f；视觉评审委派 GLM。
- **IF** 后端 / API / 数据库 / 服务端：实现委派 MiMo；要求 DSV4.1f 评审架构与接口。
- **IF** 截图 / 图片 / 视频：多模态分析委派 GLM。
- **IF** 前后端集成：DSV4.1f 协调；MiMo 负责后端；DSV4.1f 负责前端；GLM 负责视觉验收。
- **IF** 核心资产调试（按项目定义域）：归属 Asset-Debug Lead。
- **IF** 部署 / 文档 / 调研：委派 General Agent。
- **IF** 跨多领域：拆分为独立子任务，分别委派对应专家。

## 4. 执行纪律（Execution Discipline）

1. 先分析任务，再决定是否调用子代理。
2. 简单任务不必强行启动所有代理。
3. 复杂任务必须先制定实施计划。
4. 并行任务必须具有明确的文件所有权。
5. 禁止多个代理同时修改同一工作树中的相同文件。
6. 共享接口必须先定义契约，再进行并行开发。
7. 子代理完成后必须返回结构化报告。
8. 主 Agent 必须检查子代理的实际产出，不得盲目采纳。
9. 失败任务允许重新委派，但必须记录失败原因。
10. 任何测试失败都不得报告为通过。

## 5. 统一验收协议（Unified Acceptance Protocol）

每个任务必须返回：

- **Task ID**
- **Assigned Model**（主导者）
- **Modified Files**（改动文件清单）
- **Implementation Summary**（实现摘要）
- **Tests Executed**（已执行测试）
- **Test Results**（测试结果）
- **Known Issues**（已知问题）
- **Remaining Risks**（残留风险）
- **Acceptance Status**（验收状态）

验收状态仅允许：`PASS` / `PASS_WITH_WARNINGS` / `BLOCKED` / `FAILED`。

**最终合并与发布决策由 DSV4.1f 执行。**

## 6. 成本与效率控制（Cost & Efficiency Control）

- 避免无意义的多模型重复推理。
- 优先调用专业代理，而非让所有模型重复执行同一任务。
- 独立任务可以并行；有依赖关系的任务必须按顺序执行。
- 涉及共享文件、数据库迁移和发布时采用严格串行门禁。
- 复杂任务保留执行日志与验收报告。

## 7. 每次调用启动协议（Per-Invocation Startup Protocol）【关键】

> 本条款为用户强制要求，优先级高于默认路由。

**每次用户发起调用 / 新工作区启动时，编排层必须在开工前先确认以下四个主导者的归属：**

| 主导者槽位 | 默认绑定 | 说明 |
| --- | --- | --- |
| 前端主导者 | DSV4.1f | 页面 / 组件 / 交互 / 动画 / 前端框架 |
| 后端主导者 | MiMo | API / 数据库 / 服务端逻辑 / 插件与 MCP |
| 核心资产调试主导者 | DSV4.1f（可改派） | 项目核心资产调试（按项目定义域） |
| 验收主导者 | GLM | 视觉 / 多模态 / 交互验收，须基于真实产物 |

**执行方式**：

1. 用户调用后，编排层以结构化提问呈现四个槽位，列出默认绑定。
2. 用户可逐槽位确认默认，或改派给其他模型 / 角色 / 自定义人员。
3. 四个槽位全部确认（或用户声明"沿用上次"）后，方可进入任务分析与实际执行。
4. 若本次仅涉单一领域，仍须至少确认相关槽位；其余标"本次不涉及"。
5. 该次确认结果记入当日工作日志，作为本次任务的授权基线。
