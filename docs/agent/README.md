# Workspace Agent 动作编排学习指南

> 分类：**Agent 提示词优化（Agent Prompt Optimization）**
>
> 目标：让 DSH-L2D Workspace Agent 从“收到指令后调用单个工具”升级为能够理解工作区上下文、发现已有能力、组合动作、验证执行结果并清楚汇报的 Agent。

本指南是面向 Agent 的操作知识与推理规范，不是新的运行时 API，也不授权 Agent 越过现有工具和权限边界。

## 学习顺序

1. [工作区上下文与信息边界](./workspace-context.md)
2. [动作编排与能力组合](./action-orchestration.md)
3. [响应、回执与结果汇报](./response-protocol.md)
4. [可迁移的编排示例](./examples.md)

## Agent 必须遵循的总原则

- **先观察，再行动**：先读取与当前意图相关的状态；不要在状态未知时盲目重复动作。
- **先发现，再组合**：以仓库文档、MCP 工具定义和运行时能力查询为准。不要猜测工具名、参数、动作组或参数 ID。
- **组合已有能力**：新意图优先通过已记录能力的顺序组合、条件分支或有限并行实现；不要为每种自然语言请求臆造一个 API。
- **上下文最小化**：只携带完成当前动作所需的工作区信息，不读取、拼接或泄露无关会话内容。
- **执行与完成分离**：工具返回 accepted 只代表进入调度，不代表动作已经播放完成；必须尊重回执状态。
- **先验证，再宣称成功**：根据工具回执或状态快照确认结果。无法确认时如实报告“已受理 / 正在执行 / 结果待确认”。
- **失败不盲重试**：先分析 reason、冲突和当前优先级；只有在条件改变或重试安全时才再次调用。
- **动作克制**：角色表现应自然、低频、与语境相符；不要为了展示能力而堆叠动作。

## 能力来源与事实优先级

遇到冲突时按以下顺序判断：

1. 当前运行时工具定义和工具返回结果；
2. packages/dsh-l2d-mcp/README.md 中的 MCP 行为约定；
3. docs/AI-模型控制提示词.md、docs/参数读写对照.md 等项目提示词与参数文档；
4. 本指南中的组合示例。

本指南的示例是推理范式，不会扩大底层工具能力。若运行时没有某项工具、动作或参数，必须视为当前不可用。

## MCP 能力速查

仓库当前文档列出的 MCP 工具包括：

| 工具 | 用途 |
|---|---|
| l2d_emote | 将情绪意图交给 Emotion_Router |
| l2d_set_expression | 设置指定表情 |
| l2d_play_motion | 播放动作组 |
| l2d_set_pose | 设置四肢姿势 |
| l2d_gaze | 设置注视方向（归一化坐标） |
| l2d_say | 显示角色气泡文本 |
| l2d_act | 执行一段表情、动作、姿势、视线组合链 |
| l2d_get_state | 读取只读状态快照 |
| l2d_reset | 重置姿势、表情和注视 |
| l2d_workspace_ensure | 创建或复用专属 Live2D Agent 工作区 |
| l2d_workspace_status | 读取脱敏的工作区状态 |

注意：

- MCP **不提供** l2d_set_parameters 或 l2d_play_keyframes。
- 浏览器侧的 window.DSH_L2D 方法不等同于 MCP 工具，不能假设 Workspace Agent 可以直接调用。
- 具体工具是否可用，以当前 Session 实际收到的工具定义为准。

## 变更维护规则

新增或修改 MCP 工具后，应同步更新本指南的能力速查、参数约束和相关示例。示例必须经过工具定义或实现核对；不得仅凭函数命名推断其行为。
