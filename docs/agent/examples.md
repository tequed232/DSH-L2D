# 可迁移动作编排示例

> 本文示例用于训练 Agent 的组合推理方式。工具参数的最终形式必须以当前 MCP schema 为准。示例不代表所有部署都一定启用了相关工具或模型动作。

## 示例 1：让角色看向用户

**用户意图**：角色转向正前方。

推理：
1. 这是单一注视动作，不需要读取其他工作区状态。
2. 检查当前 Session 是否提供 l2d_gaze。
3. 按 schema 发送正前方坐标（通常是归一化中心坐标）。
4. 根据工具返回结果简短汇报。

不应做的事：
- 不要额外调用表情、动作和姿势工具；
- 不要将角度制数值误当作归一化视线坐标。

## 示例 2：先思考，再进入说话阶段

**用户意图**：让角色表现出思考过程，然后开始回应。

推理：
1. 这是有先后顺序的多阶段表现。
2. 检查 l2d_act 当前 schema 是否支持文档中的 phase。
3. 使用已记录的 thinking 阶段。
4. 根据动作回执判断是否结束或仍在执行。
5. 再进入 speaking 阶段；不要在思考动作尚未结束且调度状态不明时盲目重发。

可复用知识：后续遇到“听我说话”“回答我”“结束对话”等意图时，可以从 listening、speaking、settle 等已文档化阶段选择，而不是创建新 phase。

## 示例 3：角色一边挥手一边显示文字

**用户意图**：角色挥手，并显示“你好”。

推理：
1. 将目标拆为角色动作和气泡文本两个部分。
2. 检查当前工具 schema 是否存在可用的挥手动作；不要假设模型一定有名为 wave 的动作组。
3. 检查 l2d_say 是否可用。
4. 若两个操作相互独立且宿主明确支持并行，可以并行；否则先启动动作，再显示气泡，或按用户预期安排顺序。
5. 分别确认工具结果。气泡显示成功不代表挥手完成。

举一反三：用户要求“点头并说欢迎”，Agent 应寻找已存在的点头动作或姿势能力，再组合可用气泡工具；若没有点头能力，应说明限制并提供可行替代。

## 示例 4：用户正在忙，希望角色不要打扰

**用户意图**：根据工作区状态让角色安静陪伴。

推理：
1. 该请求依赖工作区上下文，因此检查 l2d_workspace_status 是否可用。
2. 只使用工具返回的脱敏状态，例如工作区标题、Session 状态和活动时长。
3. 不读取或推断用户正在编辑的文件、聊天内容或命令。
4. 如果状态显示工作繁忙，可选择低干扰、低频表现；若工具没有提供足够信息，则以用户当前明确表达为准。
5. 选择最小动作集合，避免连续动作打断用户。

## 示例 5：动作被优先级阻挡

**工具结果**：priority-blocked。

推理：
1. 识别这是调度拒绝，不是网络故障。
2. 检查返回的当前动作和优先级信息（如果存在）。
3. 不要原样无限重试，也不要无理由将所有动作提升为 FORCE。
4. 若用户意图允许等待，等待当前演出结束后再尝试；如果当前工具调用没有提供可靠等待机制，则说明暂未执行。
5. 向用户报告动作尚未开始。

## 示例 6：请求自定义关键帧动画

**用户意图**：让角色在三秒内连续摆头并眨眼。

推理：
1. 识别这是自定义关键帧需求。
2. 检查当前 Session 的工具列表。
3. 当前仓库 MCP 文档明确说明没有 l2d_play_keyframes，因此不能通过 MCP 直接完成。
4. 不得伪造工具调用或声称已播放。
5. 可以说明当前 MCP 能力限制，并建议使用已支持的预设动作或将关键帧能力作为独立功能提案。

## 示例 7：动作已经处于目标状态

**工具结果**：动作回执包含 already-open。

推理：
1. 这是状态机的幂等跳过，不是失败。
2. 不要重复发送相同打开动作。
3. 可继续执行后续独立步骤，或直接说明角色已经处于目标姿势。

## 示例 8：从已有能力推导新组合

遇到文档没有直接示例的新请求时，使用以下推导方法：

1. 将目标拆成可观察的结果（表情、姿势、动作、注视、气泡）。
2. 为每个结果找到有文档或 schema 支持的能力。
3. 检查这些能力是否共享动作槽、手臂资源或参数通道。
4. 根据依赖关系决定顺序；默认不并发提交可能冲突的动作。
5. 标记无法实现的子目标，不用虚构接口填补。
6. 执行后收集回执，并把实际结果与目标逐项对照。
7. 仅将成功验证的组合经验作为可复用案例；不要把一次未验证的计划写成系统能力。

## 经验归纳模板

当一个新组合被验证有效时，可将经验整理为：

- 用户意图类别；
- 所需的已有工具；
- 前置状态和约束；
- 动作顺序与依赖；
- 实际回执和验证方法；
- 失败路径与安全降级；
- 可复用范围及不适用条件。

经验案例应与核心系统提示词分开维护，并经过文档核验后再纳入指南。
