## 3. 提示词模板（已注册 prompt_templates，status=active）

三份模板正文以 SQLite `prompt_templates.body` 为准（本节为摘要，改动须走模板版本升级，不直接改文档）：

### gallery-character-sheet-v1 @1.0.0（character_sheet）
部件清单（按视图/细节窗定位）→ 视图对应差异 → 抄录图上文字标签（`source_exact`+quote）→ 配色 → 动态暗示（只列部件不绑参数）。铁律：只依据图内可见事实。

### gallery-static-art-v1 @1.0.0（fan_art/screenshot/photo/poster）
表情/姿态/服装/部件/画风/场景六字段标注；部件 value 必须沿用设定表词表；`linkedNodeKey` 仅在能对应真实参数族时填写；**主体不是目标角色→退回不标注**；宁可漏标，不可错标。

### gallery-gif-motion-v1 @1.0.0（gif_reference）
动作相位分解 → 逐相位 motion_cue → 循环/节奏判定 → 参数族候选（`inferred`，confidence≤0.6）；**禁止断言具体绑定**——绑定验证属 Model Inspector 的 probe_runs。

## 4. JSON 契约与 SQL 映射

- 输出契约：`tools/gallery-schema/semantic-label.schema.json`（2020-12）。标注 pass 产出 JSON → 校验 → 入库。
- 表映射（迁移 v2，`packages/dsh-l2d-db`）：
  - 图像事实 → `gallery_items`（file_name 幂等键；real_format 魔数为准；source_class 七类；review_state 四态）
  - 语义标签 → `gallery_labels`（field 九类 CHECK；evidence_level 三级；`(item_id, field, value)` 幂等）
  - **图↔模型桥** → `gallery_labels.linked_node_id`（可空外键→`nodes.id`，节点删除置 NULL 不毁标签）
  - 提示词资产 → `prompt_templates`（template_id 主键；draft/active/deprecated 三态）
- 与 v1 的关系：`semantic_labels`（模型侧，绑 node_id）不动；图库侧标签独立分表，两边靠 linked_node_id 汇合。推断数据绝不直写运行时参数。

## 5. 执行流程（Behavior Engineer 工作区）

```text
scan.mjs（盘点，已完成）
   │
   ▼
逐张视觉标注（按 source_class 选模板；HEIC 跳过并报告）
   │  产出符合 semantic-label.schema.json 的 JSON
   ▼
校验 + upsertGalleryLabel 入库（needs_review）
   │
   ▼
复核闸门（人工/多模态抽查）→ approved / rejected
   │
   ▼
Model Inspector 注册 nodes 后回填 linked_node_id（词表→node_key→node_id）
   │
   ▼
汇总进 capability_profiles（v2 起，能力画像可引用 approved 标签作证据）
```
