# 动作链编排 v1

> 目标：让 Live2D 角色对**其他 DSH 工作区的活动状态**做出「像一个有反应的人」的回应，而不是要么不动、要么抽搐。
> 数据与判定在本目录的 `packages/dsh-l2d-plugin/lib/choreography.mjs`（纯数据 + 纯函数），
> 执行器在 `tools/act-choreo/index.mjs`（开发/验收用，不进插件运行时）。
> 本轮只新增文件，未改 `lib/index.js` / `lib/workspace-agent.mjs`；接线方案见 §6。
> 日期：2026-11-02。模型：大肥鱼.dsl2d.2048（7 动作组 / 21 表情）。

---

## 1. 结论

- 7 个状态（bootstrap / thinking / working / attention / error / idle / user-direct）各配一条链，全部实测播出，**7/7 accepted + completed**。
- 优先级、同级抢占、低优先级被挡、右臂冲突、重复打开 skipped 五类回执语义全部实测符合设计（**矩阵 6/6**）。
- 抖动保护靠四道闸：状态稳定 `minDwellMs` → 同状态冷却 `cooldownMs` → 全局最小间隔 `minGapMs` → 翻转风暴静音（`flipWindowMs` 内超 `maxFlips` 次只压 BACKGROUND）。
- 环境状态（thinking / working / idle）一律 `BACKGROUND`，任何对话/事件都能打断；事件状态 `NORMAL`；用户直接对话 `FORCE`。
- 已知边缘：attention 链带一个开合动作，极偶发（ad-hoc 探测 3 次出现 1 次）收招未落地导致手停在开位，直到下一次动作或 `l2d_reset`。见 §8。

## 2. 数据口径

状态来源（只读、脱敏，不读取其他会话文本）：

| 来源 | 产出 |
|---|---|
| `lib/index.js` `deriveAgentState()` | `thinking`（user/message、step/start、assistant/message）、`working`（tool/call）、`attention`（turn/end 正常结束）、`error`（turn/end 带错误）、`idle`（>120s 无事件；error 保留 10 分钟） |
| `aggregateWorkspaceState()`（本模块） | 多个工作区/会话聚合：`error > attention > working > thinking > idle` |
| 本地事件 | `bootstrap`（专属工作区/渲染首次就绪）、`user-direct`（用户直接对 Live2D Agent 说话） |

链的步骤只有四类（与 `l2d_act` 一致）：`expression` / `motion` / `pose` / `look`。
**不写任何底层参数，口型参数禁入**（校验器会对整份数据做 `ParamMouth*` 扫描）。

时长按 `overlay.js` 的 `plannedLifeMs` 同口径估算：`life = max(400, 每步 cursor+1800, 有 closeMotion 时 cursor+closeAfterMs+200)`。
单链上限 10s，给 MCP 的 12s 轮询留余量。

## 3. 链清单

### 3.1 bootstrap · 就绪（NORMAL）

| 项 | 值 |
|---|---|
| 触发 | 专属工作区创建成功 / 叠加层首次 `ready`（每个 DSH 进程一次） |
| 步骤 | `look(0, 0.04)` → `expression 兔牙`（delay 120ms） |
| 优先级 | NORMAL |
| 估算时长 | 1920ms；实测 2217ms |
| 冷却 | 600s，600s 窗口最多 1 次 |
| 失败兜底 | 渲染未就绪直接丢，不排队、不重试 |

### 3.2 thinking · 思考（轻，BACKGROUND）

| 项 | 值 |
|---|---|
| 触发 | 其他工作区有会话 `thinking`（用户刚提交 / 正在生成） |
| 步骤 | `look(0.3, 0.32)` → `expression ＞＜`（delay 120ms） |
| 优先级 | BACKGROUND |
| 估算时长 | 1920ms；实测 2239ms |
| 抖动门 | 稳定 800ms 才触发；冷却 9s；60s 内最多 3 次；同状态不重播 |
| 失败兜底 | 被高优先级占槽就丢弃；换模型没有 `＞＜` 时删 expression 步只留视线 |

### 3.3 working · 忙活（持续，BACKGROUND）

| 项 | 值 |
|---|---|
| 触发 | 其他工作区有会话 `working`（有 `tool/call`） |
| 步骤 | `expression 加载` → `look(0.18, 0.08)`（delay 80ms） |
| 优先级 | BACKGROUND |
| 估算时长 | 1880ms；实测 2119ms |
| 抖动门 | 稳定 1200ms；冷却 8s；持续期间每 25s 补一次轻脉冲；60s 内最多 3 次 |
| 失败兜底 | 持续态只补视线脉冲，不重复播动作、不弹气泡；被占槽就等下个 refresh |

### 3.4 attention · 轮到你（NORMAL）

| 项 | 值 |
|---|---|
| 触发 | 其他工作区有会话 `turn/end` 且不是错误（等你接手） |
| 步骤 | `look(0, 0.05)` → `expression 兔牙`(120) → `motion 竖手指打开`，closeMotion `竖手指关闭`，closeAfterMs 1800，delay 200 |
| 优先级 | NORMAL |
| 估算时长 | 2320ms；实测 2607ms |
| 抖动门 | 事件状态不压翻转；冷却 15s；60s 内最多 2 次 |
| 失败兜底 | 右臂被狗尾巴草占着时动作返回 `conflict`，表情/视线已生效，**不重试**；重复打开返回 `skipped`，记进 `notes: already-open`，也不算失败 |

### 3.5 error · 出事（克制，NORMAL）

| 项 | 值 |
|---|---|
| 触发 | 其他工作区有会话 `state=error` / `hasError` |
| 步骤 | `expression 流冷汗` → `look(0, -0.14)`（delay 120ms） |
| 优先级 | NORMAL |
| 估算时长 | 1920ms；实测 2344ms |
| 抖动门 | 事件状态不压翻转；冷却 20s；60s 内最多 1 次 |
| 失败兜底 | 不弹错误文本（状态快照本身已脱敏）；表情保持到下一次 attention / 用户对话覆盖 |

### 3.6 idle · 待机（极轻，BACKGROUND）

| 项 | 值 |
|---|---|
| 触发 | 其他工作区全部 idle/unknown，且已静默 ≥8s |
| 步骤 | `look(0, 0)` |
| 优先级 | BACKGROUND |
| 估算时长 | 1800ms；实测 2114ms |
| 抖动门 | 稳定 8s；冷却 45s；90s 补一次；300s 内最多 2 次 |
| 失败兜底 | 默认就是「不动作」；只把视线收回，**不清表情**、不插手引擎待机 |

### 3.7 user-direct · 用户直接对话（FORCE）

| 项 | 值 |
|---|---|
| 触发 | 用户直接对 Live2D Agent 说话（专属会话 `user/message`） |
| 步骤 | `expression 兔牙` → `look(0, 0)`(100) → `motion 竖手指打开`，closeMotion `竖手指关闭`，closeAfterMs 2800，delay 180 |
| 优先级 | FORCE |
| 估算时长 | 3280ms；实测 3615ms |
| 抖动门 | 冷却 2s；60s 内最多 6 次；`force` 可绕过冷却（用户主动时） |
| 失败兜底 | 多轮对话优先走已有 phase 短链：`listening / thinking / speaking` 为 FORCE，`settle` 为 NORMAL（实测 listening 2605ms、thinking 2486ms、speaking/settle 用于矩阵占槽） |

## 4. 防抽搐规则（`decide()`）

判定顺序与原因码：

| 顺序 | 规则 | 不通过原因码 |
|---|---|---|
| 1 | 状态必须在映射里 | `unknown-state` |
| 2 | 翻转风暴：`flipWindowMs`(20s) 内状态翻转 ≥ `maxFlips`(4) 次时，BACKGROUND 静音（事件状态不受限） | `jitter` |
| 3 | 同状态不重播；只有 `refreshMs>0` 的持续态才在到点后补脉冲 | `same-state` |
| 4 | 状态至少稳定 `minDwellMs` | `dwell` |
| 5 | 同状态冷却 `cooldownMs` | `cooldown` |
| 6 | 任意两条链之间至少隔 `minGapMs`(1500ms) | `min-gap` |
| 7 | `windowMs` 内不超过 `maxInWindow` 次 | `rate` |
| — | 通过 | `fire` |

额外语义：`force: true`（用户直接说话）绕过 2/3/4/5/6/7，只保留链本身的合法性；不放宽优先级规则——`l2d_act` 的槽位仲裁始终由引擎执行。

实测样例（模拟翻转）：`thinking/working` 连续翻转 4 次后，thinking 返回 `jitter` 不发；同一时刻 attention 正常放行。

## 5. 优先级与打断（实测）

`BACKGROUND(10) < NORMAL(50) < FORCE(90)`；低不能打断高，同级可打断；`accepted` 只表示占槽，终态看 `events` 的 `start/end/interrupted`。

| # | 场景 | 期望 | 实测 |
|---|---|---|---|
| 1 | FORCE（phase speaking）在播，BACKGROUND thinking 插入 | 被挡 | `accepted:false`，`reason:priority-blocked`，`current.priority:FORCE` ✅ |
| 2 | NORMAL（phase settle）在播，BACKGROUND idle 插入 | 被挡 | `accepted:false`，`reason:priority-blocked`，`current.priority:NORMAL` ✅ |
| 3 | BACKGROUND working 在播，NORMAL error 抢占 | 抢占成功，旧链 interrupted | `accepted:true`，旧链 `interrupted`，新链 2236ms 完成 ✅ |
| 4 | NORMAL attention 在播，同级 NORMAL error 抢占 | 抢占成功 | `accepted:true`，旧链 `interrupted`，2248ms 完成 ✅ |
| 5 | 狗尾巴草占着右臂，attention 的动作步 | 动作 conflict，表情/视线仍生效 | `end.reason="狗尾巴草 正在占用同一批手臂参数，请先播放 狗尾巴草关闭"`，2749ms 完成 ✅ |
| 6 | 竖手指已开着，attention 再打开 | 幂等跳过，不算失败 | `end.notes:["already-open"]`，2751ms 完成 ✅ |

## 6. 接线方式（建议）

现状：`workspace-agent.mjs` 的 `refresh()` 在指纹变化且 30s 节流到期时，向专属 Agent 发一条 prompt，让它「自己决定要不要调工具」。这带来三个问题：烧 token、延迟不确定、同一状态可能被 LLM 自由发挥成别的动作。

建议改成**确定性直发 + 保留 LLM 只做「值得说话」的判断**：

1. `workspace-agent.mjs` 引入 `choreography.mjs`，在每次 `refresh()` 后：
   - `aggregateWorkspaceState(latest, workspace.id)` 得到聚合状态；
   - 用 `decide({state, previousState, stateSince, lastAnyFireAt, lastFireAtByState, fires, flips})` 判定；
   - `fire` 时把 `chain / priority` 原样发给 `l2d_act`。
2. 传输不要写死端点：由 `lib/index.js` 在创建 bridge 时注入一个 `callAction(name, args)`（内部走现有 `aiInbox` 或本机 `/dsh-l2d/ai/call`）。这样 `workspace-agent.mjs` 保持可单测、不依赖端口发现。
3. 30s prompt 只保留给「事件状态」且附带**已发生的回执**（例如「刚才 attention 链被 priority-blocked」），让 Agent 最多补一句气泡或换一个表情；环境状态不再 prompt。
4. `user-direct` 不接通知链路：用户直接说话时由对话链路以 `FORCE` 走 phase 模板（`listening → thinking → speaking → settle`），本编排只做单发兜底。

接线需要改 `lib/workspace-agent.mjs`（+ 可能在 `lib/index.js` 注入 `callAction`）并**重启 DSH**，按当前约定留给用户统一批次；本轮未动。

### 验收命令（无需重启，直接对运行中的叠加层发）

```bash
node tools/act-choreo/index.mjs --list          # 打印编排计划与时长
node tools/act-choreo/index.mjs --all           # 逐条跑 7 条链（默认间隔 1.3s）
node tools/act-choreo/index.mjs --state attention
node tools/act-choreo/index.mjs --phase speaking
node tools/act-choreo/index.mjs --matrix        # 优先级/冲突/跳过矩阵
node tools/act-choreo/index.mjs --all --out ./last-run.json
```

端点每次从 `~/.dsh/l2d-service.json` 的 `origin` 读（DSH 重启端口会变），也可用 `DSH_L2D_ORIGIN` 覆盖。
**页面必须可见**：被遮挡时 rAF 被节流，动作不推进（交接书 §5.2 的教训）。执行器会在开始/结束各读一次 `frames` 证明渲染活着。

## 7. 校验器

`validateChoreography(map, { expressions, motionGroups })` 检查：

- 7 个状态齐全、无多余状态、id 与键名一致；
- 步骤 kind 合法、未知字段报错、链 ≤8 步（MCP 上限）、估算时长 ≤10s；
- 表情名 / 动作组必须在当前模型白名单里（换模型可传覆盖表）；
- `closeMotion` 只能写配对关闭名（竖手指/狗尾巴草/抚胸手），`closeAfterMs` 300~12000ms；
- `look` 的 x/y 在 -1~1；`pose` 只允许 rest/finger/grass/chest；
- 口型参数禁入；BACKGROUND 链里出现动作步给警告（会占舞台 acting）。

`choreography.test.mjs` 覆盖上述规则与 `decide()` 的 7 个原因码、聚合优先级、时长公式，`node packages/dsh-l2d-plugin/lib/choreography.test.mjs` 通过。

## 8. 风险与未做

1. **收招偶发未落地**（P2）：attention 的 motion 步由 `closeAfterMs=1800` 定时收招；ad-hoc 探测 3 次里出现 1 次收招没生效，手停在开位，直到下一次动作或 `l2d_reset`。矩阵与 `--all` 两次复跑都没复现（可能和同优先级 `startMotion` 竞争有关）。建议后续把收招改成 `isFinished` 事件驱动，或接线层收到 `end` 后校验槽位、发现残留补一条关闭。
2. **表情粘性**：thinking/working 会切 `＞＜` / `加载`，链结束后表情保持到下一条链覆盖；idle 故意不清表情（避免抹掉用户情绪）。如果观感上「思考脸」停太久，可在 wiring 层加一条延迟 clear。
3. **多模型**：表情/动作白名单写死为大肥鱼；换模型必须传 `validateChoreography` 的覆盖表，未做运行时自省。
4. **场景未覆盖**：AWAY（锁屏/离席降帧）、媒体律动、系统传感器都不在本编排范围内（设计见 `DSH-L2D-行为系统设计-v0.1.md`）。
5. **30s 通知节流与动作节流是两层**：动作冷却 8~45s，通知节流 30s；接线后要避免「通知触发但动作被冷却吞」的观感空档，因此建议环境状态不走通知、直接由 `decide()` 驱动。
