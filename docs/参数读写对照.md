# 可写输入 / 只读输出

模型文件不在仓库里。下面不是一份抄下来的参数总表，而是**生成规则**。换模型时按同一规则重算，不要把某一版 physics3 的输出名单硬编码进提示词。

微动作调度的模块名是 **Emotion_Router**（ambient 优先级 20）。不要写成别的名字。

## 怎么区分

1. 打开模型的 `physics3.json`（`model3.json` → `FileReferences.Physics`）。
2. 每个 `PhysicsSettings[].Output[].Destination.Id` 都是**只读输出**。渲染每帧用物理结果覆盖它们。外部再写一次，看起来像没写。
3. 常见输出（仅作兜底，有 physics3 时以文件为准）：
   `ParamAngleX/Y/Z`、`ParamBodyAngleX/Y/Z`、`HipAngle*`、`ShoulderY`、手臂和手的输出（`RArm`、`LArm`、`RForearm`、`LForearm`、`RHand`、`LHand`）。
4. **不在输出表里**、注入器也接受的，才是可写输入。这套模型的头部跟踪绑定是 `AngleX` / `AngleY` / `AngleZ`，不是 `ParamAngle*`。重心一类是 `PositionX` / `PositionY`。
5. `ParamMouthOpenY`（以及 `ParamMouthOpen`）即使不在物理输出表里，也标成只读。只有将来的口型通道可以写。行为、微动作、媒体律动都不许碰。
6. 媒体律动如果要带动身体，只加到 `AngleZ`，再和注视/拖拽/微动作做加法并限幅。不要为了摆动去写嘴。

适配器 `tools/vts-adapter/index.mjs` 会把上述结果写进 `capabilities.json` 的 `paramAccess.writable` / `paramAccess.readonly`。`tools/gen-ai-tools` 生成工具定义时带上这份说明。

## 运行时再确认一次

渲染包启动后会再读一份 physics3，注入器用真实输出表拒绝无效写入。某个参数在文档里写成可写、运行时却被拒绝，以运行时为准。

`ParamEyeBallX` / `ParamEyeBallY` 的 min/max **仓库里确认不了**（模型不入库，代码里也没有写死眼球角度）。注视用 `l2d_gaze` 的 -1~1。若要直接写这两个参数，先调用 `getCapabilities()`，用返回的 `min` / `max`。不要沿用以前提示词里的 -30~30。

头部 `AngleX/Y/Z` 在这套模型上大约是 -30~30，这是交接时的实测，不是眼球的范围。写入仍会被参数自身的 min/max 钳住。

## 微动作用到的可写参数

| 语义 | 实际参数 | 说明 |
|---|---|---|
| 歪头 | `AngleZ` ±3 | 和媒体律动、拖拽侧倾加法叠加，上限约 ±15 |
| 重心 | `PositionX` ±5 | 同上，和拖拽位移叠加 |
| 耸肩 | `PositionY` | `ShoulderY` 是输出，不能写，所以用身体上下近似 |
| 鼓腮 | `CheeckPuff` | 保持模型里的拼写 |
| 嘟嘴 | `Mouthpucker` | 不是 `ParamMouthOpenY` |

参数不存在时只打一次日志并跳过，不改模型。
